# 260710_ローカルLLM環境構築

## 目的
共有ラボPC（Quadro RTX4000, RAM 128GB）にローカルLLM環境を構築し、LM Studio経由でQwen2.5-32B-Instructを使えるようにする。

## 実施内容

### 1. Python環境整備
- python.orgよりPython 3.13.14をユーザーローカルにインストール（管理者権限不要、Install for all usersはオフ）
- 初回、Microsoft Storeのダミーエイリアス（python.exe実行時にバージョン表示が異常）に遭遇 → 「アプリ実行エイリアス」でPython関連をオフにして解消
- `pip install -U huggingface_hub` 実行、huggingface_hub 1.22.0導入（CLIコマンドは`hf`に統合されている世代）

### 2. Qwen2.5-32B-Instruct-Q4_K_M.gguf ダウンロード
- 配布元: bartowski/Qwen2.5-32B-Instruct-GGUF
- 保存先: `C:\Users\ana1c\.lmstudio\models\bartowski\Qwen2.5-32B-Instruct-GGUF\`
- 学内ネットワークが不安定で、接続タイムアウト・切断が頻発（`ReadTimeout`、`peer closed connection`等）
  - `HF_HUB_DISABLE_XET=1` でXet転送を無効化し通常HTTPに切り替え
  - 自動リトライ用バッチファイル（`download_qwen.bat`）を作成し放置
  - 最終的に約9時間かけてダウンロード完了（19.85GB / 19,851,336,576バイト、サイズ一致確認済み）
- 既存モデル（Qwen2.5-Coder-32B-Instruct, Qwen2.5-14B-Instruct-1M）も同フォルダ構成で稼働中

### 3. LM Studioでのロード失敗とトラブルシューティング
- Qwen2.5-32B-Instructをロードすると `Failed to load the model / Exit code: 18446744072635812000` で毎回クラッシュ
  - 符号付き変換で約-1,073,739,616 → Windowsのアクセス違反系クラッシュコードに相当
- GPU Offload 0（CPUのみ想定）に設定しても同様のエラーで失敗
- 既存のQwen2.5-Coder-32B、Qwen2.5-14B-Instruct-1Mも同様に失敗することを確認 → ファイル固有の問題ではなくランタイム側の問題と特定
- 原因特定:
  - `nvidia-smi`確認 → Driver Version 430.86 / CUDA Version 10.2（2019年頃のバージョン、大幅に古い）
  - LM Studio Runtime設定を確認 → GGUFのデフォルトランタイムが「Vulkan llama.cpp」、CUDA llama.cppは「GPU survey unsuccessful」と表示
  - 古いドライバがVulkan/CUDAランタイムのGPU初期化に対応できずクラッシュしていたと判明
- 切り分けとして、LM StudioのRuntime設定でGGUFランタイムを「CPU llama.cpp (Windows)」に変更 → Qwen2.5-14B-Instruct-1Mが正常にロード・応答（4.84 tok/sec、正常な日本語応答を確認）

### 4. ドライバ更新
- NVIDIA公式サイトより Quadro RTX 4000 用最新ドライバをダウンロード・クリーンインストール
  - Driver Version: R595 U6 (596.72)、Production Branch/Studio、2026/6/17リリース
  - PC再起動後、`nvidia-smi`でDriver Version 596.72 / CUDA Version 13.2への更新を確認
- LM Studio Runtime側もCUDA llama.cpp / Vulkan llama.cpp / CUDA 12 llama.cppをv2.24.0へ自動更新

### 5. GPU有効化後の動作確認
- GGUF Runtimeを「CUDA llama.cpp (Windows)」に切り替え、Qwen2.5-32B-Instructを再ロード
  - GPU Offload 18、Context Length 8192設定でロード成功（クラッシュ解消）
  - `nvidia-smi`にてLM Studio.exeがComputeプロセスとして認識され、VRAM 6931MiB/8192MiB使用・GPU-Util 18%を確認 → GPUアクセラレーションが実際に機能していることを確認
  - ただし体感速度は「1秒2〜3文字」相当とまだ遅い。VRAM 8GBに対し32Bモデル（Q4_K_M, 約20GB）は全層GPU搭載不可のため、CPU-GPUハイブリッド動作となり速度上限がある構成であることを確認
- **結論：32Bモデルのロード・応答自体は正常に動作することを確認済み。速度チューニング（GPU Offload値、Context Length調整等）は別チャットで継続検討。**
