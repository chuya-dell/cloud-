# 2026/07/09 PC容量整理(ラボDell PC, Cドライブ)

## 発端
- ラボDell PCのC:ドライブがパンパン(使用済み209.1GB / 236.2GB、空き27.0GB)
- 前回スキャンとの比較で+49.1GB増加を検知

## 調査手順・結果
Microsoft PC Managerのストレージ概要で内訳確認:
- ユーザーファイル 88.8GB → AppData 69.2GB(Local 42.5GB, Roaming 26.7GB)が主犯
- Roaming内: Notion 12.2GB、Claude 11.0GB(うちvm_bundles 10.0GB)が異常肥大化
- LM Studioは未使用と判明、容疑から除外
- AppData\Local\Google\DriveFS(Google Driveキャッシュ)3.8GB

## 実施した対策(ジャンクション方式)
robocopy(/E /MOVE)でH:ドライブへ実体移動 → mklink /J で元の場所にジャンクション作成、の順で実施。

1. **Notion\Partitions** (12.2GB) → `H:\AppData_Moved\Notion\Partitions` ✅成功、正常動作確認
2. **Claude\vm_bundles** (約9GB) → `H:\AppData_Moved\Claude\vm_bundles` ✅成功(初回робocopyでファイル使用中エラー発生、Claudeデスクトップアプリ終了後に再実行して解決。smol-bin.vhdxの削除ロック残りも手動delで対処)
3. **Google DriveFS** (3.8GB) → **❌失敗、ロールバック済み**
   - ジャンクション化するとGoogle Driveアプリが起動不能に(`CANNOT_CREATE_UI`, `Called ListDir on non-directory`エラー)
   - 原因: DriveFSは低レベル仮想ファイルシステムを実装しており、ベースフォルダがジャンクションであることを想定していない模様
   - **教訓: DriveFSはジャンクション方式で移動不可。Google Drive設定内の保存先変更機能を使うか、この方式は諦めるべき**
   - `robocopy H:→C: /E /MOVE`で実体をC:に戻し、ジャンクションを削除して復旧
4. **OneDrive - 公立大学法人大阪** (8.7GB→12GB程度) → OneDriveの公式機能(「このPCからリンクを解除」→再セットアップ時に「場所の選択」)でH:へ移動
   - 移動時、既にH:に同名の実体フォルダ(以前の名残?)が存在していたため「このフォルダーを使用」で結合
   - 同期処理(2,282件の変更処理)が発生、完了待ちの状態で最終確認は未了

## 最終成果(Google Drive失敗分を除く)
- C:ドライブ使用量: 209.1GB → 179.9GB(**約29GB削減**)
- 空き容量: 27.0GB → 約56GB

## 未完了・要フォローアップ
- OneDriveの同期完了確認、C:側の古いOneDriveフォルダ(12.0GB)が空になったか確認してから削除要検討
- Google Driveは今回ジャンクション化を諦めてC:のまま運用中(3.8GB分はC:に残存)
- ProgramData(34.8GB)、Program Files等の「アプリケーションファイル」領域は今回対象外(移動リスクが高いため見送り)

## 技術メモ(今後同様の作業をする際の参考)
- ジャンクション方式(`robocopy /MOVE` → `mklink /J`)は、単一アプリの単純なキャッシュ/データフォルダ(Notion, Claude等)には有効
- 仮想ファイルシステムを実装するタイプのソフト(Google Drive DriveFS等)には不向き、そのアプリの公式「保存先変更」機能を使うべき
- OneDriveも同様に公式機能(リンク解除→場所の選択)を使うのが正解
- robocopy実行中にアプリが起動中だと「エラー32: プロセスが使用中」で削除だけ失敗することがある。事前にアプリを完全終了(タスクトレイからも終了)してから実行するのが必須
