# 2026-06-30

## 作業内容

### 基板位置合わせ ソフトウェア開発

**背景**
- デジタルカウント実験でスループット低（3条件×3反復で最大9時間）
- 基板を固定してシリアル処理しているのが原因
- 解決策：物理ランドマーク＋ソフトウェア画像レジストレーションで基板を外して再装着できるようにする

**今日やったこと**
- レーザーカッターでL字スクラッチをランドマークとして基板に刻印済み
- 位置合わせ用TIFFファイル（1-0〜1-3.tif）を撮影・確認
  - `1-0.tif`：基準画像
  - `1-1〜1-3.tif`：基板を外して再装着後の連続撮影
- `register_images.py` を開発・完成

**スクリプトの仕様**
- Step1：縦線スクラッチの傾きを各行の最暗点で線形回帰 → 回転補正
- Step2：ガウシアン背景除去後のスクラッチ位置検出 → 平行移動補正
- 出力：`registered/` フォルダに補正済みTIFF

**検出されたズレ**

| 画像 | 回転補正 | dx | dy |
|------|---------|----|-----|
| 1-1 | -0.033° | +77px | -10px |
| 1-2 | **-0.230°** | -51px | -10px |
| 1-3 | -0.003° | -47px | -10px |

**ハマったポイント**
- 照明の周辺減光（vignetting）でcol 0が最も暗くなり、argminがスクラッチを検出できなかった
- 解決：既知のスクラッチ範囲（col 30-300）に検索を限定し、回転後は元画像の位置±150pxで検索

**GitHub**
- https://github.com/chuya-dell/PC-alignment-claude に `register_images.py` をアップロード

## Claude Code版 vs Antigravity版 比較評価（2段階再位置合わせ）

両者とも「物理ランドマーク（スクラッチ溝）による粗位置合わせ＋ソフトウェア補正」という基本方針は共通。ただし設計・精度評価の深さに明確な差がある。

### 1. ランドマーク検出・粗位置合わせ

| | Claude Code版 (`register_images.py`) | Antigravity版 (`registration.py`) |
|---|---|---|
| ランドマーク | レーザーカッターL字スクラッチ、縦線の傾きを行毎最暗点の線形回帰で検出 | 既存基板の縦・横スクラッチ溝、プロファイル最小値で検出 |
| 回転補正 | あり（線形回帰で傾き算出） | 明記なし（並進のみ記載） |
| 既知の落とし穴対応 | 周辺減光(vignetting)でargmin誤検出 → 検索範囲をcol 30-300に限定、回転後±150px範囲に限定して解決 | Grid Aliasing（HCP格子5.5pxピッチでの隣接ピラー誤認）を明示的に課題として特定し、粗位置合わせを先に確定させることで回避 |

**所見**：Claude Code版は回転補正を含む点で優位。Antigravity版は格子エリアス誤認という、より本質的な失敗モード（既存ImageJ等のアライメント済みデータがX:6px/Y:60pxもズレていたまま「完了」とされていた問題）を発見・定量化している点が際立つ。これは見過ごされていたら致命的なエラー要因になり得た。

### 2. 高精度フィッティング（サブピクセル化）

- Claude Code版：レジストレーションは粗位置合わせ（回転＋並進）止まり。サブピクセル精度のための後段処理（点群フィッティング等）は現状なし。TODOに「サブピクセル精度の改善」が残っている。
- Antigravity版：粗位置合わせ後にKDTree＋SVDによるリジッドICPでピラー点群同士をフィットさせるStage 2を実装。最終的に平均残差0.86px（サブピクセル）まで収束したと定量評価済み。

**所見**：Antigravity版は2段階目（ICP）まで実装・検証済みであり、現状Claude Code版より一歩先を行っている。Claude Code版のTODOにある「サブピクセル精度の改善」は、Antigravity版のICPアプローチを参考にできる可能性がある。

### 3. 定量評価の有無

- Claude Code版：検出された回転角・dx/dyの実測値は記録されているが、精度評価指標（マッチング率、RMSE等）は未実装。
- Antigravity版：ターゲット画像ごとにマッチング率（68.81〜76.14%）、RMSE（0.86〜0.87px）を算出し、画像端の非重複領域比率（6〜7%）から妥当性を考察している。

**所見**：Antigravity版の方が定量的な検証プロセスが整っている。Claude Code版も同様の評価指標を追加すべき。

### 4. コードの堅牢性・実用面

- Claude Code版：vignettingによる誤検出という実機特有の問題を発見し、検索範囲限定で対処した実装上の工夫がある。実運用に即した試行錯誤の跡が見える。
- Antigravity版：日本語/全角パスのWindows対応（cv2.imdecode化）、明視野画像対応の`--invert`オプションなど、環境依存の実用的な対応が明記されている。

**所見**：両者とも実環境のトラブルシューティングを経ており、優劣付けがたい。

### 総合評価

- **検出ロジックの堅牢性（vignetting対策、回転補正）**：Claude Code版がやや優位
- **誤認識リスクの特定と回避（Grid Aliasing）、サブピクセル精度、定量評価**：Antigravity版が明確に優位
- 現状、Antigravity版の方が完成度・検証の深さで一歩進んでいる。Claude Code版は回転補正ロジックをAntigravity版に統合する、もしくはAntigravity版のICPステージをClaude Code版にも追加する形での統合が望ましい。
- 次のアクション候補：①両スクリプトのGrid Aliasing対策・回転補正を統合した単一パイプラインの検討、②Claude Code版にもマッチング率/RMSE評価を追加、③どちらを正式版として`PC-alignment`系リポジトリに採用するか決定。
